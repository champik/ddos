# Команда: /run month

Запустити pipeline для "кращого за попередній місяць" — автоматично визначає діапазон і застосовує recency-компенсацію.

## Використання
```
/run month
```

Без параметрів — завжди попередній місяць відносно сьогоднішньої дати.

## Діапазон дат

Визначити автоматично:
- `started_at` = перший день попереднього місяця, 00:00:00 UTC
- `ended_at` = останній день попереднього місяця, 23:59:59 UTC

Приклад: якщо сьогодні 2026-07-01 → діапазон `2026-06-01T00:00:00Z` … `2026-06-30T23:59:59Z`

## Іменування

Папка: `Month_N_YYYY_MM_DD` де дата — будь-який день **покритого місяця** (напр. `Month_1_2026_06_01` для червня).
→ зберігається в `projects/2026_06_June/` — в папці того місяця за який зроблено випуск.

Для визначення N — перевірити скільки вже є папок `Month_*` в папці відповідного місяця.

## SELECT — Recency-компенсація

Проблема: кліп з 1-го числа має 30 днів набрати перегляди, з 28-го — лише 2. Чистий popularity перекошує вибірку на початок місяця.

Рішення: основний пул + компенсаційні слоти по трьох вікнах, де пізніші вікна отримують більше слотів.

### Вікна (фіксовані по дню місяця)
| Вікно | Дні | JC/IRL слотів | Gaming слотів |
|-------|-----|---------------|---------------|
| Раннє | 1–15 | 5 | 2 |
| Середнє | 16–25 | 10 | 5 |
| Пізнє | 26–кінець місяця | 15 | 8 |

### Алгоритм

```
1. Відфільтрувати весь пул за місяць (ті самі фільтри що і в /run)
2. JC/IRL:
   a. 80 по popularity (max 5/streamer) — основний пул
   b. Recency-вікна (кліпи що НЕ потрапили в попередні слоти, по popularity desc):
      - Дні  1–15  → 5 слотів
      - Дні 16–25  → 10 слотів
      - Дні 26–кінець → 15 слотів
   c. Diversity-добавка: 10 кліпів по 1 від стрімера що ще не представлений
      (з решти пулу після a+b, по popularity desc, max 1/streamer)
   Разом: 80 + 5 + 10 + 15 + 10 = 120 кандидатів

3. Gaming:
   a. 40 по popularity (max 5/game, max 5/streamer) — основний пул
   b. Recency-вікна:
      - Дні  1–15  → 2 слоти
      - Дні 16–25  → 5 слотів
      - Дні 26–кінець → 8 слотів
   c. Diversity-добавка: 5 кліпів по 1 від стрімера що ще не представлений
   Разом: 40 + 2 + 5 + 8 + 5 = 60 кандидатів (gaming screen відсіє ~50% → ~30 пройдуть)
```

## Відмінності від /run

| | /run | /run month |
|--|------|-----------|
| Діапазон | Останні 24г | Попередній місяць |
| JC/IRL кандидатів | 100 | 120 |
| Gaming кандидатів | 50 | 60 |
| Diversity floor | ✓ (20 слотів) | ✗ (замінено diversity-добавкою) |
| Recency-компенсація | ✗ | ✓ |
| Папка | `projects/YYYY_MM_Month/` | `projects/YYYY_MM_Month/` (покритий місяць) |

## Pipeline

Той самий що `/run` і `/run special`:
1. INGEST — Twitch API з `started_at` / `ended_at` за попередній місяць
2. FILTER — ті самі правила
3. SELECT — recency-алгоритм вище замість стандартного
4. DOWNLOAD — yt-dlp, ті самі правила
5. GAMING_SCREEN — ті самі правила
6. GENERATE_EDITORIAL — edit.html, зупинка

Після GENERATE_EDITORIAL — відкрити edit.html, чекати editorial JSON.
