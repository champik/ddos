# Analytics — фідбек-луп каналу

Збирає метрики опублікованих відео з YouTube і перетворює їх на рекомендації
для відбору кліпів та креативів. Мета: система, що вчиться на результатах,
а не тільки на view_count Twitch-кліпів.

## Запуск

```bash
node scripts/pull-analytics.js                 # вікно 28 днів + звіт
node scripts/pull-analytics.js --days 14       # інше вікно
node scripts/build-analytics-report.js         # тільки перегенерувати index.html
```

**Коли запускати:** щодня на початку `/run` (Stage 1) — паралельно з INGEST,
поки качаються кліпи; збір не блокує пайплайн. Можна і вручну в будь-який момент.

**Перша авторизація:** скрипту потрібен scope `yt-analytics.readonly`.
Якщо `auth/token.json` виданий старою версією (тільки upload) — видали його
і пройди авторизацію заново при першому запуску.

## Що тягнеться і скільки

| Що | Період | Обсяг |
|---|---|---|
| Список публікацій каналу | останні 28 днів | всі (~28 епізодів + ~200-280 шортсів) |
| Per-video метрики (views, watch time, AVD, утримання %, likes, comments, subs+) | за вікно 28 днів | всі відео вікна, батчами по 50 |
| Ретеншн-криві (audienceWatchRatio) | епізоди останніх 7 днів | макс 10 відео |
| Traffic sources | за вікно | канал цілком |

Дані YouTube Analytics мають **лаг ~48 годин** — відео молодші за 3 дні у
рекомендаціях не враховуються ("недозрілі").

**CTR та impressions через публічний API недоступні** (тільки Studio).
Раз на тиждень перенось цифри руками у `analytics/manual-ctr.json`:

```json
{ "VIDEO_ID": { "impressions": 12500, "ctr": 5.2 } }
```

## Що показує звіт (index.html)

- **KPI**: епізоди/шортси за вікно, views, середнє утримання лонгформу,
  середнє додивлення шортсів, приріст підписників, тренд views/епізод 7д vs раніше
- **Рекомендації** — правила з прозорими порогами:
  - утримання епізодів <40% → тривога (cold open, перші 30с); ≥50% → ок
  - додивлення шортсів <70% → слабкий хук/задовгі; ≥90% → лупляться, добре
  - конверсія у підписку: ціль ≥1% views
  - стрімер із середніми views шортсів ≥1.5× медіани (≥2 шортси) → «бери частіше»;
    ≤0.5× → «знизити пріоритет»
  - провал ретеншн-кривої ≥5пп у першій половині епізоду → таймкод + який кліп винен
  - CTR (ручний): <4% тривога, ≥8% ціль
- **Таблиці**: епізоди (з міні-кривою ретеншну), топ-шортси, розбивка по
  стрімерах, джерела трафіку

## Як використовувати висновки

1. Стрімери з вердиктом «більше» — піднімати у відборі (SELECT) і ставити
   першими в епізоді; «менше» — знижувати пріоритет у editorial.
2. Провали ретеншну — дивитись який тип моменту стоїть на цій позиції
   і не ставити схожі кліпи на початок.
3. Тренд views/епізод — реакція на зміни креативів (превю, тайтли):
   якщо після зміни підходу тренд ▼ — відкотити.
