# Harry Potter Meme Trailer — Streamer Casting Pipeline

## Контекст

Окремий одноразовий проект (не частина основного DDOS-епізодного пайплайну): перемонтувати
трейлер "Harry Potter and the Philosopher's Stone" — на місце персонажів "кастяться"
Twitch-стрімери, репліки персонажів замінюються на реальні фрази стрімерів з їхніх кліпів.
Це мемний монтаж (сленг + голос реальної людини на місці репліки), не діпфейк — жодного
AI-генерованого лиця чи голосу, тільки підбір реального матеріалу.

Проект живе в `projects/Special/Harry Pootter/Harry Potter and the Philosopher's Stone/`
(структура директорій — своя, відмінна від `projects/<YYYY_MM_Month>/<runId>/` основного
пайплайну).

**Межа автоматизації:** система шукає і пропонує відповідні репліки (пошук за змістом у
транскриптах), користувач затверджує вибір. Візуальний монтаж (вирізання кадру, накладання
голови стрімера на персонажа — фото чи відео-бульбашка, синхронізація, склейка) —
повністю вручну, тим самим інструментом і в тому ж стилі що й основний DDOS-пайплайн
(CapCut). Автоматика не займається компонуванням відео.

## Пайплайн

```
A. TRAILER_PREP   Завантажити трейлер (yt-dlp, посилання — від користувача) → Whisper-
                   транскрипт → Claude розбиває на сцени (персонаж, репліка, timestamp),
                   спираючись на власне знання сценарію трейлера
                   → trailer/source.mp4, trailer/transcript.json, trailer/scenes.json

B. CASTING         Claude показує розбивку на сцени і пропонує стрімера на кожну роль за
                   вайбом/особистістю; для кожної ролі визначає обсяг пошуку (tier):
                   головні персонажі (багато реплік у трейлері) → ~1000 кліпів,
                   другорядні (1-2 репліки) → ~100-200 кліпів
                   ← ЧЕКПОЙНТ: користувач затверджує/править список
                   → casting.json

C. CLIP_SOURCE     Для кожного затвердженого стрімера: тягнути N кліпів (Twitch API,
                   пагінація, N = tier з casting.json). Для кожного кліпу:
                   тимчасово завантажити (yt-dlp) → транскрибувати (Whisper GPU,
                   scripts/transcribe.py) → ВИДАЛИТИ відеофайл → дописати запис у
                   phrases.json: {clipId, url, title, views, date, транскрипт-сегменти
                   з таймкодами}. Відеофайли ніде не зберігаються після цього кроку —
                   лишається тільки текстовий індекс фраз.
                   → candidates/<streamer>/phrases.json

D. PHRASE_MATCH    Для кожної сцени з scenes.json: Claude шукає в phrases.json
                   призначеного стрімера кандидатів, що пасують за змістом/гумором до
                   репліки персонажа. Показує користувачу топ-варіанти: цитата +
                   timestamp у кліпі + посилання на кліп (clips.twitch.tv/<clipId>)
                   ← ЧЕКПОЙНТ: користувач обирає варіант (або просить інший/більше)
                   → matches.json: {scene, streamer, clipId, timestamp, quote}

E. CLIP_FETCH      Для кожного затвердженого match: завантажити повний кліп (yt-dlp)
                   → selected/<NN>_<role>_<streamer>.mp4
                   Автоматика зупиняється тут. Вирізання фрагменту, підготовка
                   зображення/відео голови стрімера, накладання на кадр трейлера,
                   склейка — вручну.
```

## Файлова структура

```
projects/Special/Harry Pootter/Harry Potter and the Philosopher's Stone/
├── trailer/
│   ├── source.mp4          # оригінальний трейлер
│   ├── transcript.json     # Whisper-транскрипт трейлера
│   └── scenes.json         # [{sceneId, character, line, startTime, endTime}]
├── casting.json             # [{role, streamer, tier: "main"|"secondary", clipPoolSize}]
├── candidates/
│   └── <streamer>/
│       └── phrases.json     # [{clipId, url, title, views, date, segments:[{text,start,end}]}]
│                             # НІЯКИХ відеофайлів
├── matches.json              # [{sceneId, role, streamer, clipId, timestamp, quote}]
└── selected/
    └── <NN>_<role>_<streamer>.mp4   # повні кліпи, тільки затверджені matches
```

## Перевикористання наявної інфраструктури

- **Twitch API fetch** — логіка з `scripts/ingest.js` (fetch кліпів по broadcaster,
  пагінація) — новий скрипт лише параметризує під довільний список стрімерів/tier
  замість фіксованих категорій основного пайплайну.
- **yt-dlp download** — той самий wrapper, що й у DOWNLOAD-стадії основного пайплайну.
- **Транскрипція** — `scripts/transcribe.py` (Whisper, GPU, вже верифіковано робочий —
  див. `feedback-whisper-gpu` пам'ять) — використовується і для трейлера, і для кліпів
  стрімерів.
- **Підбір фраз/кастинг за вайбом** — рішення Claude приймаються в розмові, не через
  Anthropic API виклики зі скриптів (узгоджується з `feedback-scoring-in-conversation`
  пам'яттю — так само як SCORE у основному пайплайні).

Нового коду небагато: оркестрація fetch→transcribe→delete для CLIP_SOURCE, генерація
scenes.json/matches.json, парсинг клавіш посилань на Twitch-кліпи.

## Edge cases

- **Стрімер має менше кліпів, ніж запитаний tier** — беремо все що є, фіксуємо фактичну
  кількість у casting.json, не блокуємось.
- **Транскрипція окремого кліпу впала** (пошкоджене аудіо тощо) — пропустити кліп,
  залогувати, продовжити пул.
- **Жодна фраза в пулі не пасує сцені** — Claude прапорцює сцену, пропонує або
  розширити пул (докачати ще кліпів), або підібрати іншого стрімера на роль.
- **Сцена без чіткого персонажа** (закадровий текст, монтажна склейка без репліки) —
  Claude позначає в scenes.json окремо, вирішується разом з CASTING-чекпойнтом
  (пропускається або отримує окрему обробку за рішенням користувача).

## Що НЕ входить у цей проект

- Жодного AI face-swap/діпфейк-генерування.
- Жодної автоматичної обробки відео/фото голови стрімера (вирізання, маскування,
  bg-removal) — раніше розглядалось (Higgsfield remove_background, кругла
  reaction-cam бульбашка через ffmpeg), відкладено — користувач робить це вручну.
- Жодного фінального рендеру/склейки відео — результат системи це `matches.json` +
  завантажені `selected/*.mp4`, решта монтажу поза системою.
