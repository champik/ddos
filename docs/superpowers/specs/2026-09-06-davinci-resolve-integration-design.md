# DaVinci Resolve — автоматизація частини монтажу

## Контекст

Зараз фінальний монтаж (`docs/superpowers/specs/2026-08-02-capcut-handoff-design.md`) робиться
вручну в CapCut: обрізка кліпів, склейка епізоду, reconnecting-перебивки, накладання імені
стрімера, Shorts, субтитри. Користувач хоче перейти на **DaVinci Resolve** (безкоштовна версія)
і автоматизувати ту частину монтажу, яка не потребує творчих рішень, лишивши решту ручною —
так само, як зараз система зупиняється на `processed/clean/` + `processed/streamers_name/`
і віддає решту CapCut.

Ключове обмеження: DaVinci Resolve не headless-сервіс — застосунок має бути відкритий,
керування відбувається через його офіційний Scripting API (Python), який працює і в
безкоштовній версії (не Studio-only). Fusion-сторінка (потрібна для кастомних ефектів) теж
доступна безкоштовно.

## Межа: система vs Resolve (вручну)

### Автоматизується (V1)

```
STREAMER_NAMES (вже є, без змін)
     ↓ (користувач відкриває DaVinci Resolve)
/ddos resolve assemble <runId>   → Resolve-проєкт <runId>, таймлайн "Episode":
                                    intro → clips (порядок editorial.clipOrder) → outro,
                                    + overlay streamers_name/*.png на кожному кліпі
     ↓ (користувач ріже кліпи, вставляє reconnecting-перебивки, субтитри, Shorts, ефекти —
       вручну в Resolve, як раніше в CapCut)
     ↓ (експорт з Resolve)
/ddos resolve chapters <runId>   → exports/chapters.txt (реальні, вже порізані таймкоди)
     ↓
PUBLISH (без змін)               → /ddos approve читає exports/episode.mp4 + exports/shorts/*.mp4
```

### Лишається вручну в Resolve (без змін порівняно з CapCut-дизайном)
Reconnecting-перебивка (`assets/overlays/reconnecting-panel.mov`), trim/cuts кліпів,
субтитри, Shorts, фінальний експорт.

### Відкладено на потім (окремий майбутній спек)
Звук гліча поверх матюків — вимагає word-level таймстемпів, а TRANSCRIBE/CENSOR зараз
вимкнені (нема транскриптів, див. `CLAUDE.md`). Не входить у цей дизайн.

## Архітектура: Node "що будувати" + Python "як будувати"

Той самий поділ мов, що вже є в проєкті (Node — пайплайн/конвенції іменування, Python —
зовнішня/важка робота, як `transcribe.py` для Whisper).

- **`scripts/resolve-assemble.js`** (Node) — резолвить `getProjectDir(runId)`
  (`scripts/lib/project-path.js`), читає `edit/editorial.json` і basename-мапу
  (`scripts/lib/clip-naming.js`), будує JSON-маніфест (впорядкований список
  `{clipPath, overlayPath, streamer}`, шляхи до `assets/intro/intro_30fps.mp4` /
  `assets/outro/outro_30fps.mp4`) → пише в тимчасовий файл → викликає
  `python scripts/resolve_ctl.py assemble --manifest <path>`.
- **`scripts/resolve-chapters.js`** (Node) — резолвить `runId` → назва Resolve-проєкту/
  таймлайну → викликає `python scripts/resolve_ctl.py chapters --project-name ...
  --timeline-name Episode --out exports/chapters.txt`.
- **`scripts/resolve_ctl.py`** (Python) — вся робота з Resolve через офіційний
  `DaVinciResolveScript` модуль. Не знає нічого про DDOS-конвенції іменування — тільки
  виконує механічні операції з готових даних у маніфесті.
- Команди: `/ddos resolve assemble <runId>`, `/ddos resolve chapters <runId>` — обидві
  запускаються вручну користувачем, коли Resolve вже відкритий (без авто-запуску
  застосунку — за межами скоупу).

## `assemble`

1. Знаходить або створює Resolve-проєкт з ім'ям `runId` (напр. `Episode_44_2026_06_28`) у
   поточній Resolve-базі даних, у ньому таймлайн `Episode`.
2. Імпортує в Media Pool: intro, outro, кожен `.mp4` з `processed/clean/`, кожен `.png` з
   `processed/streamers_name/`. Імпорт пропускається, якщо файл з тим самим шляхом уже в
   пулі — повторні запуски безпечні.
3. Складає таймлайн: intro → clip1 → clip2 → ... → outro, у порядку
   `editorial.json.clipOrder`. **V1 — прості cuts, без переходів** (див. "Технічний спайк"
   нижче — переходи додаються окремим кроком лише якщо спайк підтвердить, що це
   надійно скриптується).
4. Overlay імені стрімера — окремий відеотрек, на кожному кліпі:
   - transform: 25% zoom, pan/tilt -1800/-400 (значення з CapCut-конвенції координат на
     канвасі 1920×1080 — той самий формат, що й `assets/intro/`/`assets/outro/`;
     конвертація в Resolve'івську систему координат Transform-властивостей —
     implementation-деталь, перевіряється емпірично при реалізації, рішення користувача
     тут не потрібне);
   - таймінг: з'являється на `clip_start + 1s`, фіксована тривалість `5s` (до
     `clip_start + 6s`) — незалежно від довжини кліпу. Мінімальна тривалість кліпу в
     системі — 6s (`CLAUDE.md`), тобто вікно overlay завжди вміщається;
   - **V1 — без анімації появи/зникнення**, статичний show/hide. Glitch-in (1s,
     "Flash Glitch") / glitch-out (0.5s, "Barco Mess") — з тим самим технічним спайком.
5. Захист від випадкового знищення роботи: якщо таймлайн з такою назвою вже існує в
   проєкті — `assemble` відмовляється його перебудовувати, вимагає явний `--force`.
6. Якщо якийсь файл з `editorial.clipOrder` відсутній у `processed/clean/` — abort з
   повним списком відсутнього, без часткової збірки.

## `chapters`

1. Відкриває вже існуючий проєкт (створений `assemble`), читає **поточний** стан
   таймлайну — вже після ручного трима/вставок користувача.
2. Проходить по відеотреку 1 в порядку позиції на таймлайні; для кожного айтема бере ім'я
   файлу пов'язаного медіа-кліпу, матчить проти патерну `NN_streamer_idSuffix`.
   Все, що не матчиться (intro, outro, reconnecting-панель, будь-що додане вручну) —
   пропускається, у чаптери не потрапляє.
3. Формат рядка: `m:ss StreamerName` (ім'я з великої літери, як у Shorts-конвенції).
   **Перший матч завжди отримує `0:00`** — усі інші таймкоди відліковуються відносно
   нього, а не від абсолютного початку таймлайну. Якщо перед ним є intro — реальна
   позиція у фінальному відео зсунута на тривалість intro відносно написаного в файлі;
   це свідомо прийнятий компроміс (простота формату важливіша за точну прив'язку до
   секунди intro).
4. Результат — `exports/chapters.txt`, готовий для вставки в опис YouTube вручну.
5. Якщо жоден айтем на таймлайні не матчиться (напр. все перейменовано вручну) — abort з
   поясненням, порожній файл не пишеться.

## Технічний спайк (перед V2, окрема мала задача)

Дві операції мають непідтверджену документацією підтримку в офіційному Resolve Scripting
API (на відміну від імпорту кліпів/transform-властивостей overlay, які документовані й
надійні):

- вставка Edit-переходу (Cross Dissolve, 0.5s) між сусідніми елементами таймлайну
  (включно intro→clip1, clip→clip, останній clip→outro);
- анімований glitch-ефект на overlay (glitch-in 1s / glitch-out 0.5s) — потребує
  Fusion-композиції; перед побудовою нодів з нуля перевірити **Reactor** (вбудований у
  Fusion безкоштовний маркетплейс макросів, Fusion-сторінка → Reactor) на готові
  community glitch/VHS-макроси, які можна застосувати ближче до вигляду CapCut'івських
  "Flash Glitch"/"Barco Mess", і чи їх взагалі можна вставити скриптом (а не тільки
  вручну drag&drop).

**Результат спайку визначає V2:**
- якщо обидві операції надійно скриптуються — додаються в `assemble` без зміни
  архітектури (transitions + glitch overlay effects);
- якщо ні — V1-поведінка (cuts, статичний overlay) лишається постійною, користувач
  додає переходи/ефекти вручну в Resolve, як і планував раніше в CapCut.

Спайк не блокує використання V1 — timeline assembly, overlay-позиціонування і chapters
працюють незалежно від його результату.

## Помилки та тестування

- `assemble`/`chapters`: якщо Resolve не запущений або API недоступний — чітка помилка в
  stderr, exit non-zero, нічого частково не змінюється (немає проєкту/таймлайну в
  напівстані).
- Юніт-тестами (`npm test`) покривається тільки Node-частина: побудова маніфесту з
  `editorial.json` + `clip-naming.js` — чисті функції, без залежності від живого Resolve.
- Python-частина (виклики Resolve API) — ручне/інтеграційне тестування, бо вимагає
  відкритого GUI-застосунку; так само влаштовані інші non-mockable кроки пайплайна.

## Поза скоупом

Reconnecting-перебивка (авто-вставка), звук гліча на матюках (окремий майбутній спек,
вимагає повернення TRANSCRIBE/CENSOR), автоматичний trim/cuts кліпів, субтитри, Shorts,
фінальний експорт, авто-запуск застосунку Resolve якщо він не відкритий.
